# Security policy

Only the latest development version is maintained. Do not post secrets, history or exploit details publicly. Until private reporting is configured, open an issue requesting a private contact without sensitive details.

Suggestions read tabs, bookmarks and history locally without modifying them or sending typed text to an online completion service. Explicit bookmark actions can add/remove selected page URLs directly in a user-chosen writable folder; history remains read-only. Selecting a search, destination or restored session causes normal navigation to that provider/site.

The worker validates extension senders and source windows/tabs before actions. Current-page replacement is explicit; ordinary Search opens new tabs or activates existing results. Commands are whitelisted in a separate mode. Closed-tab IDs are rechecked against Chrome's recent sessions. Custom search templates require HTTP(S), no credentials, unique keywords and exactly one query placeholder.

Local storage contains optional Site Search overrides, confirmed shortcut associations, activity settings and bounded action metadata (7 days/500 by default). Query/prompt text in the action journal is opt-in and remains until expiry or manual clear even if text recording is later disabled. AI requests also have separate recovery copies in storage.session: up to 20, hidden after 24 hours, cleared on extension reload/update/disable or browser restart. Recovery copies are written before navigation and can be manually cleared; no automatic replay occurs. Automatically inferred templates are not persisted. ClipboardWrite supports explicit URL copying; clipboard contents are never read. New permissions in 0.11 are search, sessions, storage and clipboardWrite, each documented in README.

The overlay is injected through activeTab/scripting on invocation. No host permissions, persistent content scripts, remote code, telemetry or backend are present. Its iframe isolates normal keyboard events from host page handlers; it does not protect against hostile sites removing the overlay DOM.

Changes introducing external services, wider permissions or persistent browsing data need documentation and review.

Browser-section navigation uses a static allowlist of internal Chrome destinations. It opens their UI without reading settings, passwords or installed-extension details. Arbitrary browser-action URLs (for example restart/quit) are not accepted as direct catalogue navigation.

Action history records executed operations and failures, not suggestion keystrokes; navigation labels omit query strings and paths by default. An alarms permission schedules expiry while Chrome is running. Journal settings and manual clearing are available on the extension-only activity page. The underlying providers receive submitted text in their query URL; normal browser history or provider retention can therefore also apply. AI URL handoff does not guarantee auto-submission or bypass login. No API credentials or scripts on AI origins are used.

Group management uses tabGroups metadata/update plus tabs.group/ungroup on validated source-window IDs. Selection is bounded, distinct and fully checked before mutation. Pinned tabs are not implicitly unpinned. Group operations never close tabs or invoke saved-group deletion. Creation followed by a name/color update is not atomic; a failed second step is reported explicitly. Marked selection is ephemeral; the journal records group action/count metadata under the existing policy.

Folder-scoped bookmarking validates all selected source-window tabs and a fresh native tree before writing, rejects root/managed targets and unsupported or credential-bearing URLs, and never removes folders or calls removeTree. Removal matches only selected canonical URLs directly within that folder, preserving other folders and unrelated bookmarks. Extension writes are serialized and existing URLs are skipped. Native changes outside the extension can still race; multi-bookmark operations are not atomic. Partial failures report progress; successful writes are not rolled back, and a fresh retry skips existing additions. Standard Chrome bookmark syncing applies. Action logs store operation/count metadata under the existing policy, not a second bookmark database.
