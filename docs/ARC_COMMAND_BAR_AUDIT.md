# Аудит Command Bar Arc и нашего поиска

Дата: 2026-10-30. Снимок расширения до реализации: 0.10.0.

Обновление 0.11: реализованы выбранный провайдер Chrome, Site Search с настройками, режим команд, edit-режим, восстановление сессий и навигационные модификаторы Enter. Исправлено ожидание результатов при быстром Enter. Ниже сохранён исходный аудит; актуальное поведение и ограничения описаны в README. Точное соответствие всем вариантам Arc по-прежнему не утверждается.

Основной вывод: у нас уже есть самостоятельный поиск по вкладкам и сохранённым адресам, но полного соответствия Command Bar Arc пока нет. Самые заметные пробелы — режим команд, Site Search, использование выбранного поисковика и отдельное редактирование текущего адреса.

## Границы исследования

Сопоставлены официальные страницы Arc и актуальный код проекта. Это документальный аудит, а не сравнительный прогон установленной версии Arc. Часть Help Center ссылок возвращает 404; архив release notes описывает поведение 2021–2023 годов. Исторические записи подтверждают существование возможностей, но не доказывают точную раскладку/интерфейс последнего релиза. Алгоритм ранжирования Arc не раскрыт; обещать идентичность его результатам нельзя.

Возможность переноса ниже — инженерная оценка по публичным API Chrome. Новые разрешения и сетевые запросы пока не добавлены. Пины, MRU и постоянная панель намеренно удалены пользователем; этот аудит не возвращает их в продукт автоматически.

## Что подтверждено у Arc

Официальный обзор описывает Command Bar как общую точку входа для адресов, открытых вкладок и действий браузера. Каталог содержит, например, восстановление закрытого, копирование URL, перезагрузку, дублирование, переход к истории и загрузкам. Это существенно шире нашего поиска. [Обзор](https://start.arc.net/master-multitasking), [каталог действий](https://start.arc.net/command-bar-actions).

Архив релизов отдельно документирует Site Search с ключевым словом и Tab (13 апреля 2023), Tab для поиска действий (25 мая), режим Cmd+L и повторное закрытие Command Bar (8 июня), удаление нежелательных подсказок (18 мая) и улучшения поисковых предложений (27 апреля). Эти исторические сценарии нужно перепроверить на целевой версии Arc перед фиксацией полного keyboard-контракта. [Официальный архив](https://start.arc.net/release-notes).

## Что уже есть у нас

- Вызов Cmd+T/кнопкой, окно поверх страницы и popup на защищённых страницах.
- Поиск названий и URL открытых вкладок текущего окна, закладок и истории.
- Приоритет открытых вкладок, объединение одинаковых URL, отдельное открытие главной сайта.
- Стрелки/Enter/Escape, Tab-дополнение адреса, редактирование введённого URL.
- Защита от устаревших ответов и событий клавиатуры страницы.
- Локальная обработка раскладки и опечаток; объяснение исправленных совпадений.
- Светлая/тёмная схема и относительные размеры текста.

Это реализованные свойства нашего продукта, а не доказательство, что Arc использует те же алгоритмы и правила.

## Ограничения и конкретные находки в коде

1. **Google зашит в destination.** `extension/model.js` возвращает URL Google для любого текста. Chrome предоставляет `chrome.search.query` для выбранного провайдера; понадобится разрешение `search`. Для popup нужно сохранить исходное окно, а не полагаться на «текущее». [Search API](https://developer.chrome.com/docs/extensions/reference/api/search).
2. **Нет edit-режима.** `palette-service.js` всегда создаёт вкладку для navigation. Для Cmd+L-подобного режима нужно отдельно передавать исходный tabId и начальный URL, валидировать их и выбирать create/update явно.
3. **Модификаторы Enter не учитываются.** `palette.js` проверяет только event.key; Cmd/Shift/Alt+Enter вызывают одно действие. Это подтверждённая особенность нашего кода. Какие сочетания совпадут с Arc, ещё нужно проверить живьём.
4. **Два разных сопоставления.** Первые результаты в palette.js — простое includes, после задержки worker применяет умное сопоставление. При очень быстром Enter результат может отличаться от выбора после загрузки. Это риск из анализа кода; отдельный воспроизводящий тест ещё не написан.
5. **История не полная fuzzy-база.** Прямые запросы берут до 50 исторических кандидатов на вариант раскладки, fallback — 100 недавних записей и 100 недавно добавленных закладок только при отсутствии совпадений. Старый URL с опечаткой вне выборки может потеряться. Это осознанная граница, а не эквивалент нативного omnibox.
6. **Только текущее окно.** Другие окна и профили не ищутся. Расширить поиск внутри доступного профиля технически можно; выбор окна должен быть понятным. Точное совпадение области поиска с Arc требует проверки, особенно для Spaces/Profiles.
7. **Ввод текста — пока не команды.** `reload` сейчас станет веб-запросом. Нужен явный режим, чтобы слово «закрыть» не выполнило действие вместо поиска.

Доступные Chrome-операции включают создание/активацию/обновление/перезагрузку/дублирование вкладок. Это не означает, что расширение получает доступ ко всем внутренним UI-командам Chrome. [Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs).

Восстановление закрытого можно строить через sessions, с дополнительным разрешением; это отличается от повторного открытия URL из обычной истории. [Sessions API](https://developer.chrome.com/docs/extensions/reference/api/sessions).

## Что не переносить автоматически

- Постоянный sidebar, пины и MRU: ранее удалены по прямому запросу.
- Spaces/Profile isolation, Peek/Little Arc, встроенный Split View, Arc Notes/Easels и полную замену chrome UI: это возможности браузерной оболочки. Popup, группы или отдельные окна могут быть аналогами, но не точной копией.
- Открытие popup произвольного другого расширения: наш action API не управляет чужими toolbar actions.
- Настройки движков Chrome целиком: выполнить поиск выбранным провайдером можно, читать все внутренние keyword-шаблоны/настройки таким же публичным API нельзя. Собственный Site Search потребует своих шаблонов и настроек.
- Arc Max/AI: не включать по умолчанию; это отдельная функциональность с сетевыми запросами и другим контрактом данных.

## Предлагаемые этапы

1. **Контракт поведения:** зафиксировать сценарии в таблице ниже; затем выбранный поисковик и безопасное разделение URL/query. Исправить ранний Enter.
2. **Режимы:** поиск, редактирование URL, Site Search, команды. У каждого свой индикатор, Tab и выход. Не ломать уже привычное Tab-дополнение без видимого объяснения.
3. **Качество подсказок:** новые/фоновые вкладки, недавно закрытые, favicon, полезный пустой запрос и настройка источников.
4. **Точная доводка под Arc:** живое сравнение клавиш, порядка результатов и редактирования в пользовательской версии. Не подменять такое сравнение исторической документацией.

## Минимальная матрица приёмки

| Действие | Ожидаемый контракт для расширения |
| --- | --- |
| Cmd+T, адрес, Enter | Новая вкладка, исходная страница цела |
| Выбранная открытая вкладка, Enter | Переключение без дубликата |
| Обычный запрос, Enter | Поисковик пользователя, не принудительный Google |
| Выбранный deep link / homepage | Разные, явно подписанные назначения |
| Быстрый Enter до завершения подсказок | Детерминированное правило, тест на гонку |
| Выбранный URL, Tab | Дополнение без перехода, возможность редактировать |
| `yt`, Tab, запрос | Понятный scope сайта, а не случайная подстановка URL |
| Режим команд, ввод reload | Команда с явным действием; обычный поиск не меняет смысл слова |
| Edit-режим, Enter | Изменение только исходной вкладки, явно указанное до перехода |
| Escape / повторный вызов | Закрытие, восстановление фокуса, без горячих клавиш страницы |
| Недавно закрытая страница | Восстановление сессии, не только открытие URL |
| Защищённая страница | Предсказуемый popup fallback |

Эта таблица — предлагаемая спецификация нашего продукта. Она не выдаётся за полностью проверенный контракт Arc.
