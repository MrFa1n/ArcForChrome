# Поиск в Zen Browser и направления улучшения Arc for Chrome

Дата анализа: 2026-11-23

## Краткий вывод

Arc for Chrome уже поддерживает открытые вкладки, закладки, историю, команды,
сайт-поиск, группы, заметки и быстрые ссылки. Основной разрыв с Zen Browser
сейчас не в количестве функций, а в архитектуре выдачи: Zen использует
встроенный URL Bar Firefox, который получает результаты от независимых
провайдеров и показывает их по мере поступления. Расширение Chrome сначала
показывает локальные совпадения по вкладкам, но затем ждёт общий ответ от
service worker, который собирает вкладки, закладки и историю.

Реалистичная цель для расширения — приблизить скорость и стабильность выдачи,
не пытаясь копировать недоступную нативную интеграцию браузера.

## Как устроен поиск Zen

- В Zen сочетание Cmd+T может открыть штатную плавающую URL-панель поверх
  текущей вкладки вместо немедленного создания новой. Это реализовано в
  [`ZenUrlbarController`](https://github.com/zen-browser/desktop/blob/dev/src/zen/urlbar/ZenUrlbarController.mjs).
- Результаты предоставляет архитектура Firefox URL Bar: специализированные
  провайдеры ищут по разным источникам, а отдельный muxer группирует и
  ранжирует выдачу. Результаты могут приходить частями, не ожидая самого
  медленного источника; запросы можно отменить при изменении ввода.
- Zen добавляет собственные провайдеры для команд и данных боковой панели.
  Команды, выбранные чаще, могут получить больший приоритет через
  [`ZenUBResultsLearner`](https://github.com/zen-browser/desktop/blob/dev/src/zen/urlbar/ZenUBResultsLearner.sys.mjs).
- Плавающая строка использует собственный интерфейс браузера и внутреннее
  состояние вкладок. У расширения Chrome нет эквивалентного доступа к
  внутреннему URL Bar или базе Firefox Places.

Документация Mozilla: [архитектура URL Bar](https://firefox-source-docs.mozilla.org/browser/urlbar/overview.html),
[жизненный цикл выдачи](https://firefox-source-docs.mozilla.org/browser/urlbar/lifetime.html),
[обзор логики для пользователя](https://firefox-source-docs.mozilla.org/browser/urlbar/nontechnical-overview.html).

## Текущее поведение Arc for Chrome

- `extension/palette.js` показывает локальные совпадения по открытым вкладкам,
  затем ждёт сообщение от service worker. Перед запросом стоит debounce 150 мс.
- `extension/suggestions.js` параллельно запрашивает вкладки, закладки и
  историю. Для закладок и истории выполняется поиск с исходной строкой и
  вариантом для другой раскладки клавиатуры. Итоговый список формируется после
  получения всех источников.
- При отсутствии совпадений включается дополнительный поиск в ограниченной
  выборке недавних закладок и истории.
- `extension/search-match.js` поддерживает совпадения по подстроке, точные и
  префиксные бонусы для заголовка и домена, небольшие опечатки и раскладку
  EN/RU.
- В `extension/suggestions.js` порядок источников задан явно: вкладки раньше
  закладок, закладки раньше истории. Поэтому точность совпадения не всегда
  может компенсировать преимущество источника.

Ключевые места реализации: `extension/palette.js`,
`extension/suggestions.js`, `extension/search-match.js`.

## Рекомендуемые улучшения

### P1: Постепенная выдача

Сначала показать уже доступные совпадения по вкладкам и локальным данным,
затем добавлять закладки и историю независимо, сразу после ответа каждого
источника. Один медленный API не должен задерживать весь список. Для этого
можно отправлять отдельные запросы источников или использовать долгоживущий
`runtime.Port`; при смене строки отменять или игнорировать устаревший запрос.

### P1: Стабильное взаимодействие во время обновления

Сохранять уже отображённые результаты и текущий выбор, пока приходят новые
источники. Новые строки должны добавляться или менять позиции предсказуемо,
без краткого исчезновения полезных совпадений и неожиданного сброса выделения.

### P1: Совместное ранжирование

Ранжировать совпадения всех источников по общей релевантности. Полезные сигналы:

1. точное совпадение заголовка или домена;
2. совпадение с начала заголовка/домена;
3. совпадение всех слов запроса;
4. открытая вкладка как дополнительный бонус;
5. недавность посещения и частота выбора;
6. опечатки и альтернативная раскладка как более слабые совпадения.

Сохранять небольшую группу приоритетных категорий (например, команды по
префиксу), но не ставить источник выше точности автоматически.

### P2: Кеширование и ограничение работы на каждый символ

Повторно использовать нормализованные названия и URL. Рассмотреть небольшой
локальный индекс для закладок и ограниченной истории, обновляемый через
события Chrome, с безопасным сбросом/перестроением. Сначала измерить задержку
каждого источника, прежде чем усложнять кеш. Переоценить debounce 150 мс по
реальным измерениям и оставить защиту от чрезмерного числа запросов.

### P2: Персонализация результатов

Использовать выбор результата как ограниченный сигнал релевантности: недавно
и часто выбранные команды/сайты могут подниматься выше. Данные оставлять
локально, ограничивать размер и срок хранения, дать способ очистки и не
записывать текст запросов без явного согласия. Для команд в проекте уже есть
начальный сигнал частоты в журнале действий.

## Как оценивать результат

До изменений полезно измерить:

- время до первого полезного результата (p50/p95);
- время до завершения всех источников (p50/p95);
- долю запросов, где выбран первый результат;
- количество изменений порядка строк после первого показа;
- качество первых 3 результатов на сценариях: открытая вкладка, точный
  bookmark, домен, запрос с опечаткой, EN/RU раскладка, команда.

## Ограничения и точность сравнения

Zen — браузер, а Arc for Chrome — расширение. Zen имеет доступ к нативному
URL Bar, внутренней базе истории/закладок Firefox и интеграции с жизненным
циклом вкладок. Chrome extension API ограничивает расширение отдельными
асинхронными вызовами. Поэтому можно перенести шаблоны UX — раннюю выдачу,
потоковое обновление, стабильное ранжирование и ограниченную персонализацию,
но нельзя получить идентичную интеграцию или те же внутренние данные.

В этом анализе репозитории и документация прочитаны статически; тесты и
бенчмарки не запускались.

## Дополнение по Arc

Официальные заметки Arc описывают действия прямо из Command Bar, переход к
поиску по сайту через Tab, более стабильный порядок результатов, подсказку
Paste and Go для адреса из буфера обмена и удаление отдельных подсказок.
Эти наблюдения описывают интерфейс. Формула ранжирования и устройство поиска
Arc в заметках не раскрыты.

В Arc for Chrome команды теперь находятся в обычной выдаче, а закладки и
история могут появляться независимо. Для будущих улучшений полезно оценить
локальное скрытие отдельных подсказок, ранжирование по недавности переключения
на вкладку и явное действие «Вставить и открыть». Действие вставки можно
запускать по жесту пользователя без фонового чтения буфера.

Источники: [заметки Arc за 2022 год](https://resources.arc.net/hc/en-us/articles/20498417809815),
[за 2023 год](https://resources.arc.net/hc/en-us/articles/20498377604887),
